============================================================ 0. PURPOSE
OF THIS FILE
============================================================

This file is the authoritative implementation and research context for
VYRA.

Any coding agent, including Antigravity, should read this file
completely before changing the project.

VYRA is a research-oriented navigation system. It is not a chatbot, RAG
system, generic AI agent, or dashboard-only project.

The core objective is to investigate whether forecasting the future
localization consequences of different navigation choices can improve
adaptive navigation during GNSS degradation and outages.

The system combines: - GNSS positioning - IMU sensing - inertial dead
reckoning - GNSS/IMU hybrid fusion - GNSS degradation prediction -
short-horizon localization-error forecasting - uncertainty estimation -
adaptive navigation-mode selection - controlled GNSS degradation/outage
simulation - rigorous evaluation against baselines

IMPORTANT: Do not fabricate results, dataset fields, literature claims,
accuracy numbers, or “novel” claims. If something is unknown, explicitly
mark it as needing verification.

============================================================ 1. PROJECT
IDENTITY ============================================================

Project short name: VYRA

Current research/project title: Forecast-Driven Adaptive Navigation-Mode
Selection for Resilient GNSS/Dead-Reckoning Localization

Core domain: GNSS resilience + inertial navigation + machine learning +
sensor fusion + adaptive decision-making.

Target navigation modes: 1. GNSS 2. HYBRID — GNSS +
inertial/dead-reckoning fusion 3. DR — inertial dead reckoning

The framework is NOT fundamentally limited to cars. Potential
application domains include: - vehicles - UAVs/drones - mobile robots -
industrial autonomous systems - emergency-response systems -
marine/other GNSS-assisted platforms - smartphones or wearable
navigation platforms

The initial prototype may use public GNSS/IMU data and software
simulation because that is the most practical and reproducible
implementation path.

Do not claim that results on one dataset automatically prove performance
on every platform.

============================================================ 2. SIMPLE
EXPLANATION ============================================================

Imagine a system that is currently navigating using GNSS.

GNSS can become unreliable because of: - buildings - tunnels - urban
canyons - multipath - poor satellite geometry - signal obstruction -
interference - temporary degradation - complete outage

Dead reckoning can continue estimating movement using IMU sensors, but
its error grows over time because of sensor bias, noise, orientation
errors and integration drift.

Hybrid fusion can combine GNSS and inertial information, but it is not
automatically best in every condition.

The important question is therefore not simply:

“Is GNSS bad?”

The more useful question is:

“If I choose GNSS, HYBRID, or DR right now, what localization error is
likely to happen over the next few seconds?”

VYRA investigates this idea.

At each decision point, VYRA can estimate the short-term future
consequences of the candidate navigation modes.

Conceptually:

Current state | +–> What happens if I keep GNSS? | +–> What happens if I
use HYBRID? | +–> What happens if I use DR? | v Forecast future
localization risk/error | v Select the mode expected to produce the
safest/lowest future error

This is the key conceptual shift.

Traditional reactive switching can behave like:

GNSS good -> use GNSS GNSS bad -> switch to DR

VYRA investigates a forecast-driven decision:

Current conditions -> predict future GNSS reliability -> estimate DR
uncertainty/survivability -> forecast future localization consequences
of candidate modes -> select the mode that best satisfies the error/risk
objective.

============================================================ 3. CORE
RESEARCH QUESTION
============================================================

Primary research question:

Can short-horizon, action-conditioned/counterfactual localization-error
forecasting predict the consequences of choosing GNSS, HYBRID fusion, or
dead reckoning, and can an adaptive policy use those forecasts to reduce
future error-bound violations and unnecessary navigation-mode switching
during GNSS degradation and outages?

An earlier formulation of the project focused on jointly considering
predicted GNSS reliability and DR survivability.

The current VYRA direction extends that idea by explicitly asking:

“What would likely happen if each navigation mode were selected now?”

This formulation must be treated as a research hypothesis, not as an
already-proven novel contribution.

Before claiming novelty, perform a serious literature review.

============================================================ 5. WHAT IS
ACTUALLY DIFFERENT IN VYRA
============================================================

The central investigated idea is:

Instead of making navigation decisions only from current GNSS quality or
a fixed reactive rule, estimate the short-horizon future localization
consequences of candidate navigation actions.

Candidate actions: A1 = GNSS A2 = HYBRID A3 = DR

For a horizon H seconds, estimate something conceptually like:

FutureRisk(GNSS | current state, H) FutureRisk(HYBRID | current state,
H) FutureRisk(DR | current state, H)

Then choose the action according to a clearly defined policy objective.

Possible objective: minimize predicted future error or probability of
violating an acceptable error bound, while penalizing unnecessary
handovers and unstable switching.

The exact mathematical formulation must be designed and experimentally
validated.

Do not simply create three arbitrary numbers and call them predictions.

============================================================ 6.
COUNTERFACTUAL / ACTION-CONDITIONED MEANING
============================================================

“Counterfactual” means asking:

“What would likely happen if I had chosen a different action?”

Example only — NOT a measured result:

At time t: GNSS is degrading.

Predicted error over the next 5 seconds: - GNSS: 16 m - HYBRID: 7 m -
DR: 10 m

If the acceptable bound is 10 m, HYBRID may be the preferred action.

These numbers are illustrative only.

The implementation must generate real predictions from the actual
model/data.

Possible forecasting horizons: - 1 second - 3 seconds - 5 seconds - 10
seconds

These are experimental defaults, not guaranteed optimal values.

============================================================ 7. WHY THIS
MATTERS ============================================================

A reactive policy can switch too early or too late.

Switch too early: GNSS is only temporarily degraded. The system switches
to DR. DR starts accumulating error. GNSS would have recovered soon.

Switch too late: GNSS becomes severely corrupted. The system continues
trusting it. The estimated position can become inaccurate.

The system therefore faces a tradeoff:

Early switching -> more DR exposure -> possible drift

Late switching -> more corrupted GNSS exposure -> possible position
error/jumps

Forecast-driven selection -> estimate future consequences -> choose the
lower-risk option

VYRA should measure whether this forecast-driven idea actually helps.

============================================================ 10. DATA
LEAKAGE RULES
============================================================

This is a time-series research project.

Do NOT randomly shuffle overlapping time windows across train/test.

Preferred structure:

Training trajectories -> Validation trajectories -> Unseen test
trajectories

The goal is to answer:

“Can the method generalize to an unseen trajectory?”

not:

“Can the model memorize nearby windows from the same drive?”

The forecasting model must only use information available up to the
current timestamp.

No future leakage.

Ground truth after the current timestamp must never be used as an input
feature.

============================================================ 12. GNSS
DEGRADATION PREDICTION
============================================================

The first predictive task is to estimate whether GNSS will become
unreliable in a future horizon.

Example:

P(GNSS degradation within next 5 seconds)

Potential horizons: 1s, 3s, 5s, 10s.

The model must use only current and historical information.

Start with strong simple baselines: 1. Persistence/rule baseline 2.
Logistic Regression 3. Random Forest 4. XGBoost

Only investigate deep models such as: - LSTM - GRU - TCN - Transformer

if the baseline experiments justify them.

A complex model is not automatically a better research contribution.

Evaluate: - accuracy - precision - recall - F1 - ROC-AUC - PR-AUC -
confusion matrix - calibration - false alarm rate - missed degradation
rate - warning lead time

Warning lead time is particularly important.

============================================================ 13. DEAD
RECKONING ============================================================

Dead reckoning estimates motion from inertial measurements.

Basic pipeline:

IMU -> preprocessing -> bias/noise handling -> orientation/coordinate
transformation -> motion propagation -> position/velocity estimate ->
uncertainty estimate

Potential methods: - strapdown inertial propagation - velocity/position
integration - orientation estimation - EKF - error-state EKF

The implementation must document mathematical assumptions.

Do not hide assumptions.

============================================================ 14. DR
UNCERTAINTY ============================================================

The DR module must output more than a position.

It should provide:

Estimated position + uncertainty/covariance

The policy needs to know not only where DR thinks the system is, but how
uncertain that estimate is.

Possible outputs: - position covariance - uncertainty radius - standard
deviation - predicted error distribution

The exact representation should be chosen based on the estimator and
dataset.

============================================================ 15. DR
SURVIVABILITY
============================================================

DR survivability asks:

“If GNSS becomes unavailable for the expected outage duration, can DR
remain within an acceptable error bound?”

Inputs may include: - current IMU quality - current DR uncertainty -
current motion characteristics - expected outage duration -
historical/predicted DR error growth

Conceptually:

Current DR state + expected outage duration + uncertainty/error growth
-> probability or estimate of staying within error bound

Do not invent a survivability score without defining what it means.

If using a score, define it mathematically and validate it.

============================================================ 16. NEW
VYRA FORECAST ENGINE
============================================================

This is the key new direction to investigate.

At a decision time t, the system evaluates candidate modes.

For each action:

GNSS HYBRID DR

estimate the expected localization outcome over a short horizon H.

Possible prediction targets: - future position error - future error
magnitude - probability of exceeding an error threshold - expected
maximum error over horizon - expected terminal error - expected error
growth

A strong research formulation may use:

P(error(t+H) > E_threshold | current state, action)

or:

ExpectedError(action, H)

or a multi-objective risk:

Risk(action) = weighted future error + error-bound violation
probability + handover penalty + instability penalty

The exact formulation must be researched and justified.

Do not hard-code arbitrary weights without validation.

============================================================ 17.
FORECASTING APPROACH
============================================================

Possible first implementation:

For each decision time: 1. Construct a historical feature window. 2.
Encode current GNSS/IMU/navigation state. 3. Define the candidate
action. 4. Forecast the future localization consequence for that action.
5. Repeat for GNSS, HYBRID and DR. 6. Compare forecasts. 7. Select the
action according to the policy objective. 8. Execute only the selected
navigation mode. 9. Log the actual future outcome for evaluation.

This creates action-conditioned examples.

Potential training target: future error at H seconds.

Alternative: future maximum error over H seconds.

Alternative: binary threshold violation.

The best target should be selected experimentally.

============================================================ 18.
IMPORTANT DISTINCTION: PREDICTION VS SIMULATION
============================================================

The system may use controlled software simulation to generate GNSS
degradation and outages.

However:

A simulated GNSS outage is NOT the same as real RF jamming.

The UI and paper must explicitly call it: “Simulated GNSS outage”

Do not claim: “Real GNSS jamming”

The simulation should modify recorded data in a controlled, reproducible
way.

============================================================ 19.
NAVIGATION POLICY
============================================================

The adaptive policy receives information such as: - GNSS quality -
predicted GNSS degradation probability - DR uncertainty - DR
survivability - expected outage duration - current navigation mode -
predicted future error/risk for each candidate mode

Outputs: - GNSS - HYBRID - DR

The policy should not simply be a hidden collection of arbitrary if/else
statements.

Thresholds and decision weights must be: - documented - configurable -
tuned only using training/validation data - frozen before final test
evaluation

The policy should include mechanisms to prevent unstable rapid
switching.

Possible mechanisms: - hysteresis - minimum dwell time - switching
penalty - confidence margin

These must be experimentally justified.

============================================================ 51.
ONE-SENTENCE PROJECT EXPLANATION
============================================================

VYRA is a forecast-driven navigation framework that predicts the
short-term localization consequences of GNSS, hybrid fusion, and dead
reckoning choices, then adaptively selects the navigation mode expected
to minimize future localization risk during GNSS degradation and
outages.

============================================================ 52.
THREE-LINE PROJECT EXPLANATION
============================================================

VYRA monitors GNSS and inertial navigation conditions and predicts
whether GNSS reliability is likely to degrade.

It forecasts what could happen to localization if GNSS, HYBRID, or DR
were selected over a short future horizon.

It then selects the navigation mode expected to provide the best future
error/risk tradeoff and evaluates that decision against conventional
reactive switching.
