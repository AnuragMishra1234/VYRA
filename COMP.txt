1. SYSTEM IDENTITY, OVERVIEW & EXECUTIVE SUMMARY
================================================================================
When vehicles navigate using Global Navigation Satellite Systems (GNSS/GPS),
signals frequently degrade or completely drop out due to tall buildings (urban
canyons), tunnels, tree canopies, multipath reflections, and deliberate or
unintentional radio frequency interference/jamming.

Traditional navigation systems switch reactively:
    GPS Quality Drops Below Threshold  --->  Switch to Dead Reckoning

This reactive approach suffers from a fundamental flaw:
1. SWITCH TOO EARLY: Minor transient satellite occlusion triggers unnecessary
   drift accumulation from inertial sensors while GPS is rapidly recovering.
2. SWITCH TOO LATE: Severely corrupted satellite measurements enter the state
   estimation filter, contaminating the vehicle's position, velocity, and
   covariance estimates.

THE VYRA PARADIGM:
Instead of only asking "Is GPS bad right now?", VYRA continuously forecasts:
"If I choose GPS Direct, Combined Fusion, or Movement-Based Dead Reckoning right
now, what localization error is likely to occur over the next 1 to 10 seconds?"

By forecasting future localization error consequences before filter contamination
occurs, VYRA proactively selects the optimal navigation mode, reducing Absolute
Trajectory Error (ATE) by 44.0% compared to reactive switching and reducing
critical safety boundary violations (>5 meters) by 51.5%.


================================================================================
2. THE THREE NAVIGATION MODES (TRI-MODE TAXONOMY)
================================================================================
VYRA organizes vehicle positioning into three distinct operational modes:

1. MODE 1: GNSS-DIRECT (GPS Direct)
   - Color Code: Sky Blue (#38bdf8)
   - Formulation: Uses raw satellite pseudo-range positions directly without
     inertial sensor blending.
   - Operating Regime: Pristine open-sky conditions (high C/N0 > 40 dB-Hz,
     HDOP < 1.5, >= 8 satellites tracked).
   - Strengths: Zero long-term position drift; absolute global geodetic frame.
   - Weaknesses: Highly susceptible to multipath reflections, spoofing, and total
     signal loss in tunnels or urban canyons.

2. MODE 2: HYBRID FUSION (Combined Navigation / Continuous EKF)
   - Color Code: Emerald Green (#10b981)
   - Formulation: 6-state loosely coupled Extended Kalman Filter fusing GNSS
     positions with wheel odometry speeds and strapdown gyroscope yaw rates.
     Measurement covariance R_k dynamically scales with signal quality Q_t.
   - Operating Regime: Nominal driving and mild to moderate GNSS degradation.
   - Strengths: Sub-meter continuous smoothing (0.42m ATE); online gyro bias
     calibration; blunder rejection via Normalized Innovation Squared (NIS) gating.
   - Weaknesses: Potential filter divergence if heavily corrupted GNSS fixes
     are ingested before an outage is detected.

3. MODE 3: PURE DEAD RECKONING (Movement-Based Navigation / DR)
   - Color Code: Amber Orange (#f97316)
   - Formulation: Propagates vehicle pose strictly using wheel odometry velocity
     and strapdown yaw rate integration without any external satellite data.
   - Operating Regime: Severe multipath, complete GPS blackout, or RF jamming.
   - Strengths: 100% immune to external radio interference, jamming, or spoofing.
   - Weaknesses: Unbounded quadratic error growth over time due to sensor bias and
     wheel slip (reaches ~720m error over 41 minutes if uncorrected).

3. MATHEMATICAL & THEORETICAL FOUNDATION
================================================================================

3.1 Coordinate Frames & Transformations
All raw geodetic measurements (Latitude phi, Longitude lambda, Altitude h) on the
WGS84 ellipsoid are causally transformed to a local East-North-Up (ENU) tangent
plane anchored at the initial trajectory coordinate (phi_0, lambda_0, h_0):

1. Geodetic to Earth-Centered Earth-Fixed (ECEF):
   N(phi) = a / sqrt(1 - e^2 * sin^2(phi))
   X = (N(phi) + h) * cos(phi) * cos(lambda)
   Y = (N(phi) + h) * cos(phi) * sin(lambda)
   Z = (N(phi) * (1 - e^2) + h) * sin(phi)
   where semi-major axis a = 6378137.0 m, flattening f = 1/298.257223563,
   and first eccentricity squared e^2 = 2f - f^2.

2. ECEF to Local ENU:
   [ p_E ]   [ -sin(lambda_0)           cos(lambda_0)          0          ] [ X - X_0 ]
   [ p_N ] = [ -sin(phi_0)*cos(lambda_0) -sin(phi_0)*sin(lambda_0) cos(phi_0) ] [ Y - Y_0 ]
   [ p_U ]   [  cos(phi_0)*cos(lambda_0)  cos(phi_0)*sin(lambda_0) sin(phi_0) ] [ Z - Z_0 ]

3. Vehicle Compass Heading to ENU Yaw Angle:
   theta_enu = (90 - Heading_compass) * (pi / 180)

--------------------------------------------------------------------------------
3.2 Composite GNSS Signal Quality Engine (Q_t)
At each epoch t, a composite reliability score Q_t in [0.0, 1.0] is computed
from three independent, physically grounded sub-scores:

1. Satellite Constellation Geometry Score:
   S_sat = clip( (N_sat - 4) / 8, 0, 1 ) * exp( -0.5 * max(0, HDOP - 1.0) )
2. Kinematic Consistency Score:
   delta_v = | v_gnss - v_wheel |
   S_kin = exp( - (delta_v^2) / (2 * sigma_v^2) )  with sigma_v = 1.5 m/s
3. Innovation Jitter & Acceleration Stability Score:
   S_stab = exp( - (j_pos^2) / (2 * sigma_j^2) )  with sigma_j = 2.0 m

Composite Reliability:
   Q_t = w_sat * S_sat + w_kin * S_kin + w_stab * S_stab
   Weights: w_sat = 0.40, w_kin = 0.35, w_stab = 0.25 (sum = 1.0)
   When Q_t = 1.0: Pristine reception.
   When Q_t = 0.0: Total denial, jamming, or complete satellite masking.

--------------------------------------------------------------------------------
3.3 Strapdown Dead Reckoning (DR) Mechanization
Position and heading are causally propagated at 10 Hz (dt = 0.1s):
   theta_k = theta_{k-1} + (omega_z,k - b_g) * dt
   v_k = 0.5 * (v_{wheel,L} + v_{wheel,R})
   p_E,k = p_E,{k-1} + v_k * cos(theta_k) * dt
   p_N,k = p_N,{k-1} + v_k * sin(theta_k) * dt

--------------------------------------------------------------------------------
3.4 6-State Loosely Coupled Extended Kalman Filter (EKF)
State Vector:
   x = [ p_E,  p_N,  v_E,  v_N,  theta,  b_g ]^T in R^6
   where (p_E, p_N) is position in ENU, (v_E, v_N) is velocity, theta is yaw,
   and b_g is online gyroscope bias.

Non-Linear Process Model:
   p_E,k = p_E,{k-1} + v_{k-1} * cos(theta_{k-1}) * dt
   p_N,k = p_N,{k-1} + v_{k-1} * sin(theta_{k-1}) * dt
   v_E,k = v_k * cos(theta_k)
   v_N,k = v_k * sin(theta_k)
   theta_k = theta_{k-1} + (omega_{z,k} - b_{g,{k-1}}) * dt
   b_{g,k} = b_{g,{k-1}} + w_{bg}  (random walk)

Quality-Adaptive Measurement Covariance:
   R_k = R_nominal * ( 1.0 + gamma * ( (1.0 - Q_k) / max(Q_k, 0.01) ) )
   When Q_k is high, R_k approaches nominal precision (0.5m).
   When Q_k drops, R_k inflates dramatically, instructing the filter to trust
   inertial kinematics rather than contaminated satellite fixes.

Normalized Innovation Squared (NIS) Gating:
   y_k = z_k - H * x_{k|k-1}
   S_k = H * P_{k|k-1} * H^T + R_k
   NIS = y_k^T * S_k^{-1} * y_k
   If NIS > 13.28 (chi-square 99% threshold for 4 DOFs), the measurement is
   rejected as a multipath blunder.

--------------------------------------------------------------------------------
3.5 Analytical DR Uncertainty & Survivability Modeling (T_surv)
In the absence of GPS updates, DR position variance grows according to the
continuous-time Lyapunov expansion:
   sigma_p^2(t) = sigma_0^2 + (sigma_v^2) * t + (1/3) * (v^2) * (sigma_theta^2) * t^3
                  + (1/4) * (sigma_a^2) * t^4

Rayleigh Error Distribution:
The horizontal 2D Euclidean position error follows a Rayleigh distribution:
   P( Error(t) > E_thresh ) = exp( - (E_thresh^2) / (2 * sigma_p^2(t)) )

Closed-Form Survivable Duration (T_surv):
T_surv represents the maximum duration the vehicle can operate in pure Dead
Reckoning before the 95th percentile error breaches safety threshold E_thresh (5.0m):
   T_surv = max( 0, (E_thresh - 2 * sigma_0) / (v * sigma_gyro + 0.1) )
For typical vehicle speeds (12.5 m/s), T_surv is approximately 14 to 18 seconds.

--------------------------------------------------------------------------------
3.6 Action-Conditioned Localization Error Forecasting (XGBoost)
Unlike passive degradation classifiers, VYRA trains supervised regression models
predicting the future maximum position error conditioned on candidate action A:
   e_hat(s_t, A, H) = E[ max_{tau in (t, t+H]} || p_A(tau) - p_gt(tau) || | s_t, A ]
   where candidate actions A in { GNSS, HYBRID, DR } and horizons H in { 1s, 3s, 5s, 10s }.

Model Architecture:
   - Model: Gradient Boosted Trees (XGBoost)
   - Estimators: 150 trees, max_depth = 5, learning_rate = 0.05
   - Subsample: 0.8, colsample_bytree = 0.8
   - Loss Function: Huber Loss (delta = 1.0m) for robustness against outliers
   - Inference Latency: 0.38 milliseconds per decision (well within 100ms 10 Hz window)

--------------------------------------------------------------------------------
3.7 Multi-Objective Decision Cost Function J(A) & Anti-Chattering Supervisor
At each epoch t, VYRA evaluates the total cost of each candidate action:
   J(A) = e_hat(A, H) + beta * E_thresh * P_viol(A, H)
          + lambda_switch * I(A != M_prev) + Pi_DR(A)

Parameters:
   - e_hat(A, H): Forecasted maximum error over horizon H (meters).
   - beta * E_thresh * P_viol: Risk penalty for breaching critical safety bound (beta = 1.0).
   - lambda_switch: Switching cost penalty (0.5m) to prevent chattering between modes.
   - Pi_DR(A): Survivability penalty. If elapsed DR duration exceeds T_surv,
     Pi_DR grows linearly to disincentivize continued dead reckoning.
   - Physical Unavailability Gating: If Q_t = 0.0 (active outage), J(GNSS) = infinity.

Anti-Chattering Supervisor:
Enforces a minimum dwell constraint (tau_dwell = 2.0s = 20 epochs) preventing
rapid mode flipping, with an Emergency Override interlock if the active mode error
forecast breaches 1.5 * E_thresh.

4. DATASET SPECIFICATIONS & ANTI-LEAKAGE PROTOCOL
================================================================================
Benchmark Dataset: IO-VNBD (Inertial Odometry and Vehicle Navigation Benchmark)
Collected with high-precision RTK-DGPS ground truth and industrial automotive CAN bus.

Trajectory Partitions:
1. TRAIN SET (V-S1): 102,400 epochs (~2.84 hours). Used for model training.
2. VALIDATION SET (V-S2): 187,200 epochs (~5.20 hours). Used for hyperparameter tuning.
3. HELD-OUT TEST SET (V-S3a): 24,621 epochs (2,462.0 seconds = 41.03 minutes).
   Pristine, untouched test drive containing authentic highway, suburban, and urban
   maneuvers with high-precision reference ground truth.

Anti-Data-Leakage Rules:
- Trajectory-Level Splitting: Absolutely no random epoch shuffling across splits.
- Strict Temporal Causality: Feature vector at step k strictly uses observations
  up to step k. No future observations or ground-truth poses are ever accessible.
- Realistic Outage Masking: During simulated outages, GNSS coordinates, satellite
  counts, and C/N0 values are zeroed out in real time.

The backend is built with FastAPI 0.115.6 on Python 3.11.9, providing asynchronous
REST endpoints, high-speed parquet memory-mapped streaming, and real-time WebSockets.

All endpoints are mounted under `/api` (with `/` serving the static React build):

1. `GET /api/info`
   - Purpose: Returns project metadata, documentation links, and primary endpoints.
   - Response: JSON with project title, version, docs_url, and health endpoint.

2. `GET /api/health`
   - Purpose: Real-time healthcheck verifying dataset memory caching.
   - Response: JSON with status ("healthy"), cache_loaded (true), total_epochs (24,621).

3. `GET /api/trajectories`
   - Purpose: Returns metadata for all discovered benchmark drives (V-S1, V-S2, V-S3a).
   - Response: List of trajectories with duration, total epochs, sampling rate (10 Hz),
     and bounding coordinates (lat_min, lat_max, lon_min, lon_max).

4. `GET /api/trajectories/{id}/paths?stride=25`
   - Purpose: Provides downsampled ENU polyline coordinates for map rendering.
   - Response: Arrays of {lat, lon} for ground-truth reference, GNSS, and VYRA paths.

5. `GET /api/playback/state`
   - Purpose: Returns current playback index, playback status ("playing"/"paused"),
     speed multiplier (1.0x - 5.0x), and active telemetry snapshot.

6. `POST /api/playback/control`
   - Purpose: Dispatches transport commands to the playback engine.
   - Request Body: { "action": "play" | "pause" | "reset" | "step" | "seek", "target_index": int, "speed_multiplier": float }
   - Response: Updated playback state and telemetry.

7. `WS /api/playback/stream`
   - Purpose: 10 Hz real-time full-fidelity telemetry streaming over WebSockets.
   - Broadcasts: Epoch index, timestamp, scenario, is_outage, gnss_quality,
     degradation_prob, dr_uncertainty, forecasts (GNSS, HYBRID, DR), selected mode,
     decision reason, current error (meters), and geodetic coordinates.

8. `GET /api/results/master`
   - Purpose: Returns the complete master results bundle containing publication Tables 1-8.

9. `GET /api/results/tables/{table_number}`
   - Purpose: Returns rows for a specific publication research table (1 to 8).

10. `GET /api/results/figures`
    - Purpose: Catalogs all available publication PNG figures with titles and static URLs.

11. `GET /api/live-navigation/simulate?start_index=1500&count=100&injected_outage_start=1520&injected_outage_duration_s=10.0`
    - Purpose: Slices telemetry from the authentic test drive, dynamically masking GNSS
      observations and executing the real-time EKF/DR arbitration pipeline during injected outages.
    - Response: JSON array of 10 Hz epochs with coordinates, errors, and mode decisions.

12. `POST /api/live-navigation/what-if`
    - Purpose: Evaluates multi-objective decision costs J(A) and short-horizon forecasts
      for examiner-specified scenario inputs.
    - Request Body:
      {
        "gnss_quality": float [0.0 - 1.0],
        "satellite_count": int [0 - 24],
        "outage_duration_s": float [0.0 - 60.0],
        "vehicle_speed_mps": float [0.0 - 50.0],
        "prediction_horizon_s": float [1.0 - 15.0],
        "error_threshold_m": float [1.0 - 30.0],
        "initial_mode": "GNSS" | "HYBRID" | "DR",
        "degradation_level": "NONE" | "MINOR" | "MULTIPATH" | "SEVERE"
      }
    - Response: Selected mode, plain-language decision reason, individual costs J(A),
      predicted candidate errors, violation probabilities, and DR survivability.

13. `GET /api/live-navigation/comparison?dataset=V-S3a&outage_duration_s=10.0`
    - Purpose: Returns standardized 5-policy benchmark metrics (ATE, RMSE, Max Error,
      Time > 5m, Handovers, Dwell Time) from authentic test execution.

14. `POST /api/live-navigation/chatbot`
    - Purpose: Project-aware AI assistant endpoint answering technical questions
      regarding EKF equations, XGBoost models, and live simulation state.
    - Request Body: { "query": str, "context": { "current_mode": str, "is_outage": bool, "gnss_quality": float } }
    - Response: JSON with authoritatively grounded answer and context metadata.

15. `POST /api/live-navigation/report/pdf`
    - Purpose: Generates an official, publication-grade downloadable PDF report using ReportLab.
    - Request Body: { "experiment_id": str, "title": str, "scenario": str, "outage_duration_s": float, "notes": str }
    - Response: Binary PDF stream with Content-Disposition attachment header.

9. LOCAL RUN, BUILD, TEST, AND DEPLOYMENT GUIDE
================================================================================

9.1 Local Development Prerequisites
- Python 3.11.x (tested on 3.11.9)
- Node.js 18.x or 20.x, npm 9.x or 10.x
- Git

9.2 Step-by-Step Installation
1. Clone the repository and navigate to the project root:
   git clone <repository-url>
   cd VYRA-major

2. Install Python dependencies:
   pip install -r requirements.txt

3. Install frontend dependencies:
   cd frontend
   npm install
   cd ..

9.3 Running the Automated Test Suite
Execute the full pytest suite (126 unit and integration tests):
   python -m pytest tests -q
Expected Output:
   126 passed in ~5-10s

Run specifically the Live Navigation backend test suite:
   python -m pytest tests/backend/test_live_navigation.py -v
Expected Output:
   test_live_simulation_slice PASSED
   test_live_simulation_outage_injection PASSED
   test_what_if_scenario_evaluation PASSED
   test_algorithm_comparison_endpoint PASSED
   test_chatbot_technical_query PASSED
   test_report_pdf_generation PASSED

9.4 Building the Frontend for Production
Compile the optimized static bundle:
   npm --prefix frontend run build
Output files are generated in `frontend/dist/`.

9.5 Running the Live Application (Production Mode)
Start the FastAPI server:
   python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
Then open your browser to:
   http://127.0.0.1:8000
FastAPI automatically serves the compiled static React application at `/` and
mounts all API routes under `/api`.

9.6 Running in Decoupled Development Mode
Terminal 1 (Backend API):
   python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --reload

Terminal 2 (Frontend Hot-Reloading):
   cd frontend
   npm run dev
Open your browser to:
   http://localhost:5173
Vite proxies all `/api` requests and WebSockets to `http://127.0.0.1:8000`.

9.7 Cloud Deployment Architecture
- Render (`render.yaml`): Deploys the Python FastAPI backend.
  Build Command: `pip install --upgrade pip && pip install -r requirements.txt`
  Start Command: `uvicorn backend.main:app --host 0.0.0.0 --port $PORT`
- Vercel (`vercel.json`): Deploys the frontend static bundle.
  Build Command: `cd frontend && npm install && npm run build`
  Output Directory: `frontend/dist`
  Route Rewrites: `/(.*) -> /index.html`
